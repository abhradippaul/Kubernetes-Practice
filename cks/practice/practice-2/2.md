## Task 2

### CiliumNetworkPolicy – Deny Egress (Layer 3)

**Namespace:** `team-azure`

An existing policy `default-allow` permits all traffic. Create a deny policy named `p1` that blocks egress from `role=messenger` pods to `role=database` pods.

```yaml
apiVersion: "cilium.io/v2"
kind: CiliumNetworkPolicy
metadata:
  name: p1
  namespace: team-azure
spec:
  endpointSelector:
    matchLabels:
      role: messenger
  egressDeny:
    - toEndpoints:
        - matchLabels:
            role: database
```

**Verify:**

Get the database pod IP:

```bash
kubectl get pod -n team-azure database-pod -o jsonpath='{.status.podIP}'
```

Test connectivity (should time out):

```bash
kubectl exec -n team-azure messenger-pod -- curl -m 3 <IP_ADDRESS>
```

## Task 4

### Falco – Custom Alert Format for Shell-in-Container

**Namespace:** `sahara`

Override the default Falco rule to use priority `ALERT` and a custom output format. Place the override in `/etc/falco/falco_rules.local.yaml` so it persists across Falco updates.

**Required output format:**

```
ALERT <timestamp_no_nanoseconds>,<user_id>,<container_id>,<image_repository>
```

**Rule override:**

```yaml
- rule: Terminal shell in container
  desc: A shell was used as the entrypoint/exec point into a container with an attached terminal.
  condition: >
    spawned_process and container
    and shell_procs and proc.tty != 0
    and container_entrypoint
    and not user_expected_terminal_shell_in_container_conditions
  output: >
    %evt.time.s,%user.uid,%container.id,%container.image.repository
  priority: ALERT
  tags: [container, shell, mitre_execution]
```

Restart Falco to apply:

```bash
systemctl restart falco
```

> **Reference:** [Falco Supported Fields – evt field class](https://falco.org/docs/rules/supported-fields/#evt-field-class)

## Task 9

### Ingress Resource with TLS

**Namespace:** `space` | **Service:** `rocket-server`

Create an Ingress named `rocket-ingress` that routes traffic on path `/` using hostname `rocket-server.local` with TLS from the `rocket-tls` secret.

First, check the service port:

```bash
kubectl describe deployment rocket-server -n space
```

**Ingress manifest:**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: rocket-ingress
  namespace: space
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - rocket-server.local
      secretName: rocket-tls
  rules:
    - host: rocket-server.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: rocket-server
                port:
                  number: 80
```

Add the Ingress controller IP to `/etc/hosts`:

```bash
echo "<CONTROLLER_IP> rocket-server.local" | sudo tee -a /etc/hosts
```

## Task 12

### API Server Audit Policy

Enable audit logging at `/var/log/cluster-audit.log`. Retain logs for **10 days**, max **10 MB** per file, up to **3** backups.

> **Note:** Keep a backup of `kube-apiserver.yaml` at `~/` before making changes.

**Policy file** at `/etc/kubernetes/cluster-policy.yaml`:

```yaml
apiVersion: audit.k8s.io/v1
kind: Policy
omitStages:
  - "RequestReceived"
rules:
  - level: Metadata
    verbs: ["delete"]
    resources:
      - group: ""
        resources: ["secrets"]
    namespaces: ["kube-system"]
  - level: Request
    verbs: ["create", "update", "patch", "delete"]
    resources:
      - group: "apps"
        resources: ["deployments"]
    namespaces: ["default"]
  - level: Metadata
```

**Add flags to `kube-apiserver.yaml`:**

```yaml
- --audit-policy-file=/etc/kubernetes/cluster-policy.yaml
- --audit-log-path=/var/log/cluster-audit.log
- --audit-log-maxage=10
- --audit-log-maxbackup=3
- --audit-log-maxsize=10
```

**Add volumes and volume mounts:**

```yaml
# volumes
- hostPath:
    path: /etc/kubernetes/cluster-policy.yaml
    type: File
  name: audit-policy
- hostPath:
    path: /var/log
    type: Directory
  name: varlog

# volumeMounts
- mountPath: /etc/kubernetes/cluster-policy.yaml
  name: audit-policy
  readOnly: true
- mountPath: /var/log
  name: varlog
```

**Verify:**

```bash
kubectl get pods -n kube-system
ls -l /var/log/cluster-audit.log
```

## Task 13

### AppArmor Profile + Least-Privilege ServiceAccount

**Namespace:** `omni` | **Pod:** `frontend-site`

The pod has excess permissions and exposes `/internal/` publicly. Fix both without creating new service accounts.

**Step 1 – Load the AppArmor profile:**

```bash
apparmor_parser -q /etc/apparmor.d/frontend
aa-status | grep restricted-frontend
```

**Step 2 – Use the correct ServiceAccount:**

| ServiceAccount     | Extra Permissions | Action      |
| ------------------ | ----------------- | ----------- |
| `frontend-default` | None              | ✅ Use this |
| `frontend`         | Yes               | ❌ Delete   |
| `fe`               | Yes               | ❌ Delete   |

**Step 3 – Recreate the pod:**

```yaml
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: nginx
  name: frontend-site
  namespace: omni
spec:
  securityContext:
    appArmorProfile:
      type: Localhost
      localhostProfile: restricted-frontend
  serviceAccountName: frontend-default
  containers:
    - image: nginx:alpine
      name: nginx
      volumeMounts:
        - mountPath: /usr/share/nginx/html
          name: test-volume
  volumes:
    - name: test-volume
      hostPath:
        path: /data/pages
        type: Directory
```

**Step 4 – Delete unused ServiceAccounts:**

```bash
kubectl -n omni delete sa frontend
kubectl -n omni delete sa fe
```
